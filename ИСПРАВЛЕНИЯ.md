# 🔧 Исправления протокола взаимодействия клиента и сервера

## ❌ Проблема (оценка 3/10)

**Комментарий преподавателя:**
> "Некорректно реализован протокол взаимодействия клиента и сервера. Сервер не знает количество байт, которое необходимо прочитать."

### Что было не так:

1. **Сервер не знал размер массива**
   - Клиент отправлял массив байт
   - Сервер читал в буфер размером 8192 байт
   - Для массивов > 8192 байт требовалось несколько вызовов `read()`
   - Сервер отправлял timestamp после КАЖДОГО `read()`, а не после получения всего массива

2. **Неправильные измерения RTT**
   - Для больших массивов (> 8192 байт) сервер отправлял несколько timestamp
   - Клиент получал только первый timestamp
   - Остальные timestamp оставались в буфере и читались на следующих итерациях
   - Результаты измерений были неточными

---

## ✅ Решение

### Реализован протокол с явной передачей размера:

**Client.java (изменения):**
```java
// Используем DataOutputStream для отправки размера
DataOutputStream dataOutput = new DataOutputStream(socket.getOutputStream());

// Сначала отправляем размер массива (4 байта)
dataOutput.writeInt(arraySize);
// Затем отправляем сам массив
dataOutput.write(data);
dataOutput.flush();
```

**Server.java (изменения):**
```java
// Используем DataInputStream для чтения размера
DataInputStream dataInput = new DataInputStream(clientSocket.getInputStream());

// Читаем размер массива (4 байта)
int arraySize = dataInput.readInt();

// Читаем ТОЧНО arraySize байт
byte[] data = new byte[arraySize];
dataInput.readFully(data);

// Отправляем timestamp ПОСЛЕ получения всего массива
String timestamp = dateFormat.format(new Date());
writer.println(timestamp);
```

---

## 🎯 Преимущества нового протокола

1. **Сервер знает размер:** Клиент явно сообщает размер массива
2. **Точное чтение:** `readFully()` читает ТОЧНО указанное количество байт
3. **Один массив → один timestamp:** Гарантируется правильное соответствие
4. **Работает для любых размеров:** От 8 байт до 100+ КБ
